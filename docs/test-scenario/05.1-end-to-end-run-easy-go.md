# End-to-end, the easy way — 5 steps

A condensed version of `05-end-to-end-run.md` for a first-time user: five things
to do, in order, mostly by just talking to the agent. See `05-end-to-end-run.md`
for the full explanation of what each step does and why.

---

## Step 1 — Create the scenario folder and fill "User input"

Create a new workspace folder (e.g. `my-test-scenario-1`, outside `.claude/`)
and, inside it, a `User input/` folder with three subfolders:
- `Expected input/` — one realistic input the component will work on.
- `Expected output/` — a sample of what a *good* result looks like.
- `Context/` — the component's purpose, any rules/policy, and the component itself
  (or a path to it).

## Step 2 — Scaffold the test scenario

Ask the agent:

> Use the clone-test-scenario skill and create a new test scenario my-test-scenario-4

**Result:** three new folders appear next to `User input/`: `bundle/`,
`harness/`, and `test-scenarios/`.

## Step 3 — Check and fix `runs_dir`

Open `test-scenarios/<your-scenario-id>/scenario.config.md` and review the run
parameters. In particular, check `runs_dir: ...` and point it at a directory
**outside this repository** — that is where every test run's output will be
written, and it must not be committed alongside the scenario itself.

## Step 4 — Run the test

Ask the agent:

> Use the run-test-scenario skill to run the test scenario "my-test-scenario-4"

**Result:** folders with the run output appear under the `runs_dir` you set in
Step 3 (one folder per run, named `live-<timestamp>` or `replay-<timestamp>`).

## Step 5 — Summarize the results

Ask the agent:

> Use the create-test-run-summary skill to generate a summary for the completed scenario runs

**Result:** a human-readable `.md` summary (pass-rate, per-run verdicts, judge
scores, cost, failure detail) appears in the scenario's own `test-results/`
folder. The run folders it just summarized are moved into a `Complete/`
subfolder under `runs_dir`, so the next summary only covers new runs.

---

That's the loop: repeat Steps 4-5 for more runs (a fresh live run, a replay
check, a benchmark, …), or go back to Step 1 for a new scenario.
