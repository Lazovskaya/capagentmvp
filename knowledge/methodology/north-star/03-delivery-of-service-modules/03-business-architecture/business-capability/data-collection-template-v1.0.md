| Definition | captures the ownership of the business capability.Is it Manged Globally or Regionally or Locally. |

| Maturity |  |
| Definition | Maturity Level captures how well-developed a capability or asset is today and where you want it to be. This needs to be explained to the customer during the workshop and this input has to come from AM Flat team. |
| Values | Description |
| Ad-hoc | Work is informal, undocumented and person-dependent. |
| Repeatable | Basic, stable routines exist and can be repeated for similar cases. |
| Defined | Processes are documented, standardised and (often) automated across teams. |
| Managed | Outcomes are measured; KPIs and SLAs are tracked to control quality. |
| Optimised | Continuous improvement is embedded; the capability consistently drives business value. |
| Strategic Importance |  |
| Definition | strategic significance of this Business Capability for the business (Gartner Pace Layering approach) |
| Values | Description |
| Commodity | Business capability maintains commodity and operational needs, but does not provide any competitive advantage. |
| Differentiation | Business capability is important to achieve excellence in order to compete with and differentiate from others. |
| Innovation | Business capability is critical to competitive advantage. |

| Level of Customization |  |
| Definition | Determines how much SAP functionality related to the business capability is tailored to meet business requirements |
| Values | Description |
| High | Extensive custom development (e.g., Z-transactions, custom tables, user exits, enhancements, or custom Fiori apps) has been implemented to meet business needs not supported by standard SAP. Standard processes are heavily modified. |
| Medium | Standard SAP functionality is mostly used, but with notable enhancements or moderate customizations (e.g., custom reports, adapted workflows, minor ABAP development). Core process logic remains standard. |
| Low | SAP standard functionality is used with minimal or no custom development. Only configuration and master data adjustments are used to meet business needs. |
|  |  |
| Standardization Potential |  |
| Definition | Determines the potential to leverage SAP standard (processes, applications etc) to address requirements of business capabilities. |
| Values | Description |
| High | The business capability can be fully or nearly fully supported using SAP standard functionalities with minimal configuration. Little to no customization is expected. |
| Medium | SAP standard provides a reasonable base, but moderate configuration or enhancements are needed to meet business needs. Some trade-offs may be required. |
| Low | he standard SAP solution does not sufficiently support the business capability without significant customization or workaround solutions. Fit-gap is substantial. |
|  |  |
| Innovation Potential |  |
| Definition | Identifies the potential for modernizing SAP-driven processes using new technologies like AI, automation, or cloud capabilities related to the business capabiltiy |
| Values | Description |
| High | here is clear potential to significantly improve or reimagine processes using modern SAP innovations (e.g., SAP BTP, AI, ML, RPA, embedded analytics). The capability area is ripe for modernization or transformation. |
| Medium | Some potential exists to introduce modern technologies to improve efficiency or flexibility. Innovation opportunities are viable but may be incremental or require further assessment. |
| Low | Little to no benefit expected from applying new technologies. The processes are either already optimized, standardized, or not suitable for technology-driven innovation at this time. |
